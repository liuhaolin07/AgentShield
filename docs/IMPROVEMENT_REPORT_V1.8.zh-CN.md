**AgentShield V1.8 改进报告 · 2026-10-10**

V1.8 已在 V1.7 架构上实现来源感知的显式污点追踪 MVP，并完成本机真实 HTTP 验证、四组对照、首次保留集实验和回归检查。当前证据支持：在来源分类正确、数据处理使用受支持包装操作、输出经过中间件的条件下，来源策略能够阻断扫描器无法识别的敏感数据。尚不能据此声称具备完整信息流安全或覆盖任意 LLM Agent 行为。

开发分支为 [`codex/v1.8-taint-tracking`](https://github.com/liuhaolin07/AgentShield/tree/codex/v1.8-taint-tracking)，[PR #2](https://github.com/liuhaolin07/AgentShield/pull/2) 保持草稿状态。V1.7 基线为 `d1e0552949570a657955420c7b294e728a52866d`，冻结实验候选为 `b3a280888d43072627704bf021557780a02d18c8`，完成实现、测试和 CI 配置的提交为 `68f47a10e1092a0d8dfef76997b8b9817a47bb44`。本报告归纳这些已有证据，不修改历史实验结果，也不发布正式版本。

改进围绕以下执行链完成：文件／可信工具返回 → 来源分类 → 不可变污点值 → 显式转换 → 中间件扫描与来源策略 → HTTP／模型输出 → 独立接收端及执行证据核对。

污点传播不依赖扫描器重新匹配转换后的字符串。审计只记录来源／引用标识、来源类别、受支持操作链和判定原因，不记录原始敏感值。标识描述来源关系，不是数据身份或审计完整性的密码学证明。

资源限制包括：每个值最多 65,536 个聚合字符串字符、2,048 个结构节点、16 层嵌套、32 个标签、128 条来源轨迹。包装文件／配置读取、JSON 预检查、编码输出、转换步骤及分段数量也有上限。超过限制的错误不会被计为成功完成或防御成功。详见 [TAINT_TRACKING.md](TAINT_TRACKING.md)。

新实验数据集版本为 `v1.8-explicit-flow-1`。开发集包含 14 个攻击、6 个正常和 3 个测量控制，共 23 个样本；保留集包含 5 个攻击、4 个正常和 2 个控制，共 11 个样本。每组固定运行种子 17，重复 3 次，合计 408 次样本评估。重复不增加独立攻击类型的数量。

四组共享同一冻结输入、工具、执行器、接收端和任务契约，并共享来源标注与显式转换，仅切换防御执行。No Defense 关闭防御执行；Static Rule 使用历史五条原始模式及文件／域名策略；Scanner 使用 V1.7 有界扫描与策略；Scanner + Taint 增加来源约束及严格追踪检查。测量 canary 在四组中统一关闭防御并验证真实送达，计为控制样本。所有真实发送仅到固定 `127.0.0.1` 接收端，使用伪造数据，没有真实凭据或实时 LLM 推理。

每组开发集排除 9 次控制评估，保留集排除 6 次；其中包括未支持控制的 UNRUN。两次正式运行没有缺失／无效证据排除。今后攻击或正常样本若为 UNRUN、缺少接收／执行／审计证据，则从分类指标分母排除并单独披露。分母为零时保留未定义，不补造指标。

延迟是同一案例／重复与 No Defense 的中间件总检查时间配对差值：开发集每组 60 对，保留集 27 对，包含策略解析、判定和审计 I/O，不包含文件／转换／网络执行。所有组共享标签与转换，因此不是完整污点追踪开销；负测量噪声保留，不能据此声称某组在生产环境更快。

开发集 Scanner 下的 36 次实际送达、保留集的 12 次实际送达，在加入污点来源约束后均于发送执行器进入前被阻断。这些案例的扫描结果为阴性，阻断归因独立标为 `taint`，覆盖未知格式、编码、切片重组、嵌套 JSON、分段转换、混合值和模型边界传播。已知 PASSWORD 夹具同时触发扫描与污点，不作为污点独有贡献。合法请求和敏感 canary 实际到达，排除了全面拒绝请求或环境断网造成的虚假收益。

Static Rule 的两类开发集误报来自普通 PASSWORD 文档和合法 `password_policy` 参数，三次重复合计 6 次。Scanner 与 Scanner + Taint 在本数据集正常案例上均无误报。这仅描述已测试样本；粗粒度污点会保留整个容器／切片的来源，仍可能在其他正常任务中误阻断。

仍然存在的安全缺陷与研究限制：

- **来源分类依赖可信配置。** 错误／遗漏分类的未知格式数据能外传，负对照已经观察到真实送达。实验默认来源标注正确，未测量自动分类准确率。
- **包装域依赖可信代码。** 严格输出会拒绝丢失包装的普通字符串，但有权限的调用者可重新用 `literal()` 标为普通值；负对照也观察到送达。标签不可变不意味着不可伪造，直接导入工具也可能绕过集成。
- **任意运算不受完整追踪。** 第三方内部转换、模型改写、隐式流、跨原始调用重构和任意二进制格式不在当前保护范围。未支持案例为 UNRUN，不能当作防御成功。
- **工程边界尚未闭合。** 文件检查／打开竞态、真实提供方重定向及地址变化、审计篡改仍待处理；审计和来源 DAG 未签名。
- **统计与任务边界有限。** 数据集小、作者自编、底层敏感值种类少；没有实时 LLM 推理。TCR 验证的是发送任务的实际执行契约，不证明任意自然语言任务完成。

当前结果适合支撑显式来源传播机制的可行性、扫描盲点补足、追踪丢失处理、正常流放行及阻断归因等窄范围结论。0% ASR 和 0% FPR 属于上述冻结合成数据集的探索性结果，不能推广为总体安全性、未知攻击防御率或统计显著优越性。

后续投稿实验应优先补齐：外部独立攻击／正常数据集与新冻结保留集；真实多轮 LLM Agent 任务和语义完成判据；自适应攻击、未支持转换及模型改写研究；来源分类错误和策略错误敏感性；粗粒度污点误报与显式解污点设计；更强且公平的对照；单独测量标签、传播、内存和端到端成本；随机化运行顺序、统计不确定性及第三方复现。保留集一旦参与后续调参，应保留历史结果并建立新的独立验证集。
