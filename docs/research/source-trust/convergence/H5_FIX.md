# H5 设计错配修复：明确机制适用范围

用户要求“修复问题”后，本包采用最小设计修订：**保持现有策略和面板，H5 在当前
全叶声明 identity 子集中改为预设机制限制对照，不再充当首轮共同优越性主判据。**
这是研究角色的明确变更，不声称原协议从未有问题，也不把“无法区分策略”包装成
新的安全能力。没有添加新防御、改标签为遗漏或用真值驱动防御。

## 为什么这样修

conservative 只修改 MIXED 来源的默认敏感性；本面板所有叶都由显式声明覆盖，
结构标签相同，precision/conservative 均启用相同的字段精度和显式传播。
identity 的 get_item 路径因此获得相同标签。两策略共有的扫描与执行检查也不提供
所需的策略差异。在这个限定路径中，H5 的正向降低要求没有可作用的机制。

加样本、降阈值、把 PUBLIC 声明删掉或把 conservative 改成全部拒绝，都不是当前
研究问题的修复。前两项掩盖设计错误，后两项改变干预/机制。首轮更有价值的目标是
测量显式错标风险与可用性，并如实记录默认值策略的适用限制。

## 协议差分与追溯

原始 `../protocol-draft.json`、PR #5 的 255 文件及 PR #6 原始 11 文件均不改。
[protocol-amendment.json](protocol-amendment.json)引用原协议摘要、修复指令、适用子集
及六个冻结机制文件摘要。`protocol_amendment.load_effective_protocol()` 是新研究
解释的入口；原图生成器继续读取不变的数值设计，生成图和行数不受角色修订影响。

| 项目 | 原草案 | 本次有效设计 |
| --- | --- | --- |
| H5 角色 | joint_primary | prespecified_mechanism_scope_control |
| 首轮整体优越性主张 | 以 H5 共同条件为目标 | 不提出该整体主张 |
| H1–H3 | prespecified_secondary | 原角色和全部数值判据保留，不自动升格为主假设 |
| H4 | 后续条件假设、未选择机制 | 不变 |
| H5 数值定义 | AUC 降低 .05、TCR 非劣 .05、绝对 TCR .80，全部 AND | 原样保留用于追溯和后续数值描述；不能因数值偶然满足而绕过机制适用性检查 |
| 多重比较 | 首轮17统计量、10000次重采样、seed1729 | 全部保留，不因角色修订减少校正项 |
| 行预算 | E0/E1 54,720；E3 3,600；pilot984 | 不变；不删除 conservative 行，不新增面板 |

论文定位仍是测量与机制边界，不需要以某个防御改进显著作为完成条件。H1–H3 的
预设检验、风险/可用性曲线以及 H5 的机制限制各自报告，不合成一个“整体有效”分数。
阈值依据、功效、共同区间、覆盖和缺失最坏界仍待实现/验证；本修订不替代这些证据。
H5 相关数值在后续研究中仍按原17项计划报告，不因预期相同而删行、直接填0或跳过测量。

这是在尚无新材料、没有 holdout 结果的情况下作出的设计修复，不是结果揭示后的
假设切换。最终协议仍为 Draft，旧方案批准不被扩写为这次修订已独立评审/注册。
新材料或保留材料若超出当前适配子集，必须先验证相应作用路径，不能套用此静态结论。

## 可执行约束

`mechanism_applicability.inspect_identity_pair()` 只接收防御声明投影、来源正文和输出
路径；从冻结代码复算两策略的来源标签及 get_item 后的活动标签，不读取评测真值或
任务结果。图共享校验仍在编排层完成。返回结果包含声明/来源/输出路径摘要，并标记：

```json
{
  "state": "STRUCTURAL_NO_CONTRAST",
  "interpretation": "MECHANISM_SCOPE_CONTROL_NOT_SUPERIORITY_EVIDENCE",
  "empirical_hypothesis_supported": null,
  "superiority_claim_allowed": false,
  "runtime_equivalence_outside_scope": false
}
```

此结果随 `probe_identity()` 的观测返回，避免执行时丢失设计解释。
`require_h5_superiority_design()` 从实际输入重新检查，不能靠传入一个手写的
contrast=true 标志放行。当前子集下它明确拒绝 H5 优越性设计。
运行时源码摘要变化、不完整声明、不支持的变换或新的真实标签差异均拒绝沿用结论；
需要调查实现/协议差异，而不是自动转成 H5 成功。

这是一项范围有限的静态传播检查，加上真实本机合成集成验证。它不是全局等价证明、
经验等效性检验或显著性结果；也不能证明接收端之外的外发路径完整性。

## 回归覆盖与下一步

- E0 和全部75个 E1 条件，文件/工具两入口、攻击/正常两个选择路径，共304个静态
  标签传播检查；包含全部比例、方向与五个种子，不产生网络请求或研究样本。
- 协议仅改 H5 角色及明确解释元数据；禁止阈值/预算变更、H1升格、校正项缩减、
  揭示 holdout 后沿用修订、运行时换版及任务范围外推。
- 原36个合成执行探针继续运行，每条观测附机制适用性；不把它们计入984行 pilot。

本子集的设计错配现已处理。完整科学证据仍待开发材料、控制臂、观测与统计实现、
外部保管和注册。当前没有独立开发材料，故没有启动 pilot；缺材料不能通过代码
“修复”为已收集。若未来要验证一种能够纠正显式错误声明的新机制，应另立方案与
预算，并保留本轮机制限制结论作为对照。
