# 审核通过后的正式开发计划

本计划随审核材料一同提交。当前状态为待批准，本次没有开始这些工作包的实现。
审核通过后，先记录批准范围和材料快照，再从D1开始推进。

## 开发目标

把已有研究原型整理为可用、可审查的开发执行链：材料与任务输入、来源绑定、策略执行、
实际接收与任务回执、失败/缺失、攻击查询成本和分析端点使用一致的契约。
保留既有H1–H5边界、H5显式修订和预算约束。
既有执行材料按历史版本保留，新实现使用新版本和新账本，不改写旧结果以使其匹配新实现。

## 工作包及完成标准

| 优先级 | 工作包 | 具体交付 | 完成标准 |
| --- | --- | --- | --- |
| D1 / P0 | 统一任务、执行与结果契约 | 任务/变换范围、源与授权绑定、标准结果状态及版本标识 | 区分计划、有效调用、框架拒绝、运行时阻断、实际送达、正常完成、观察失败和未知；每条结果可追溯源、任务、图和执行器版本 |
| D2 / P0 | 执行器与观测链集成 | 在受控入口执行契约支持的工具调用，独立本机接收、任务回执与控制 | 敏感实际送达、正常完成和误阻断分别判定；不得把未行动、错误或缺失算作防御成功；明确当前变换支持表，超范围显式报错 |
| D3 / P1 | E3攻击算法及查询账本 | 固定定向攻击与匹配随机的家族/成本约束，记录开发查询含失败 | 每开发任务最多20查询；每次查询可追溯且失败也计数；匹配家族、逐家族k和叶宇宙；保留集不适应；不产生隐含模型请求 |
| D4 / P1 | 账本到分析端点 | 完整计划分母、逐格覆盖、暴露率、ASR/TCR/FPR及最坏缺失界 | 未执行条件保留未知；覆盖不足不通过；零暴露返回null；导出所需统计输入时列出缺失项，不补造观测 |
| D5 / P1 | 统计方法与阈值定稿准备 | 对原覆盖反例复核、比较可行方法、说明簇独立性/采样假设和原阈值精度 | 给出可复核依据；候选不满足精度时明确报告；方法或协议变更须显式记录，不能根据有利结果选择并宣称门禁完成 |
| D6 / P2 | 集成验收与开发移交 | 相应测试、范围说明、环境依赖、变更差分及问题台账 | 重要失败路径和回执经过验证；文档与实现一致；历史冻结材料与新版本可区分，形成可审核的交付 |

D1–D4可在作者开发夹具上实现与验证。执行费用、研究样本和独立性应分别记账。
D5可先完成数学/工程论证，真实功效与材料独立性仍取决于后续实际证据。
本轮待批工程工作包不预设新增付费模型请求；此前DeepSeek最多16次的开发轮已经完成。
