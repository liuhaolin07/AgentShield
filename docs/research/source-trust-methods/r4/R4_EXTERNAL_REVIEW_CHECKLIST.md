# R4 External Review Checklist：来源可信性研究设计

**阶段：Methodology Review Phase。** 这是供导师、统计研究者与 LLM Agent 安全研究者讨论的作者准备材料。以下问题参照机器学习与系统安全研究常见的审阅关注点组织，不是 NeurIPS／USENIX Security 官方清单、外部审稿意见或第三方认可。

证据快照：[R4 `0c4c635`](https://github.com/liuhaolin07/AgentShield/tree/0c4c63597fce79b1e698bfa26f60f10bb883934e)。先读[短报告的 Executive Summary](ADVISOR_REVIEW_BRIEF.md#executive-summary供首次讨论的一页摘要)。本清单不改变冻结协议、阈值、估计器或预算；[当前状态](readiness.json)仍不支持预注册、pilot 或保留集。

## 使用方法

先核查已有证据，再标注“充分／不足／不适用”，附具体文件、假设或反例。标为不适用须说明如何收窄论文声明。以下是审阅问题，尚无真实答复；不要将作者的核查器称为独立研究者，不要将模拟证据转述为防御实测。

建议统计与安全领域分别审阅，再讨论交叉问题；二者均需独立形成意见，不能用另一方的认可替代自身判断。新实验请求须先形成可审查设计，不能为了填满清单直接启动运行。

## A. 研究贡献与估计对象

| ID | Reviewer 会追问什么？ | 回答所需证据／当前缺口 |
|---|---|---|
| A1 | 相对 APPA、FIDES、AgentFlow，哪些贡献是已有机制，哪些是新的测量问题？ | [文献矩阵](../../source-trust/LITERATURE_MATRIX.md)只是初步定位；还需工件级核对干预、暴露条件分析和作者机制的差异。不能把签名、字段标签或审查成本本身作为首次贡献。 |
| A2 | 测量研究能否在 H5 不成立时仍回答科学问题？ | 分开失真曲线／暴露率与系统优越性声明；负结果不删除。收窄为探索研究时也须保留数据来源、局限与不确定性。 |
| A3 | 估计的是固定 cohort 的随机错标期望，还是任务／来源总体的效果？ | 明确样本空间、任务权重、图生成机制与独立单位；当前固定 cohort 不支持总体泛化。原来的五张固定图平均效果与随机图期望不能互换。 |
| A4 | 5% AUC 改善、80% TCR、5% 非劣及 2% 等效由什么任务风险决定？ | 需要任务所有者给出泄露与未完成损失、风险容忍度；目前尚无价值授权。不得根据已有结果放宽门槛。 |

## B. 统计设计与可证伪性

| ID | Reviewer 会追问什么？ | 回答所需证据／当前缺口 |
|---|---|---|
| B1 | 不可行证明针对什么，是否误推广到 AgentShield 或其他估计器？ | [解析范围](SCOPE.md)只针对固定 GHO-1：5／30 图下必要条件不可能满足。82／113／145 是单项最优必要界，不是联合功效或获批样本量。 |
| B2 | 17 项同时覆盖与完整 H5 的交并决策是同一种保证吗？ | 不是。须分别列声明族、alpha 分配、有效分量检验和区间解释；IUT 不能静默取代冻结同时区间要求。H5 的 13 分量与第一阶段的 17 项须区分。 |
| B3 | 图内配对、比例嵌套和全局定额相关是否正确保留？图间为何独立？ | 需要真实随机机制及跨图共享块审查；家族、任务、图条件和模拟次数不等于独立图数。清单总计 81 条件不等于每点 81 张独立图。 |
| B4 | 缺失与攻击成功／任务失败相关时，分母与结论是否改变？ | 固定全分母、最坏识别界及 95% 观测门禁；保留 UNRUN 与缺失来源，不只分析 eligible。不能将缺失假设默认为 MAR。 |
| B5 | 候选是否在小样本、零方差、稀有共同故障和跨图相关下有效？ | 审原定理及范围；[候选核查](CANDIDATE_METHODS.md)中的经验 Bernstein 必须保留小样本修正。已有 percentile 欠覆盖反例不能被更窄区间掩盖。替代方法仍未选择／校准。 |
| B6 | 新方案是否同时验证数学可行性、联合功效和错误确认率？ | 三者分别审查。事前锁定完整六点向量、一次 E0、缺失／依赖模型、不利与边界控制及校准精度；零错误／200 次不等于充分错误率保证。[未来验证问题](VALIDATION_DESIGN.md)尚非执行协议。 |

## C. 威胁模型与语义真值

| ID | Reviewer 会追问什么？ | 回答所需证据／当前缺口 |
|---|---|---|
| C1 | 攻击者能否合法错误授权 `PUBLIC`、修改 Schema、控制工具输出或 runtime？ | 分离诚实错标、授权滥用、消费链过时和未授权伪造；分别列能力与可信组件。[原威胁模型](../../source-trust/RESEARCH_DESIGN.md)需安全研究者质疑。HMAC 完整性不证明语义授权。 |
| C2 | “公开”是对谁、什么用途、哪个 sink 而言？合法模型读取是否被算成泄露？ | 需要叶级读者／用途授权与 HTTP／模型边界契约；把未经允许的输出与合法任务依赖区分。二值标签的表达限制须写入论文。 |
| C3 | 攻击命中与成功的真值是否由独立人员而非接收结果定义？ | 需要盲化双人标签、证据、`D_read/D_out`、第三人仲裁和独立审计；[TA-2](../r3/TRUTH_TRANSFORMATION_TA2.md)哈希链只能固定记录。作者 fixture 不是真人独立证据。 |
| C4 | 不确定、分歧和审计错误会不会被静默改成公开或剔除？ | `UNCERTAIN` 不得投影为 `PUBLIC`；冻结严重错误、抽样与全量重做规则。No Defense 只验证载荷／观测，不反向决定入组。真人执行与语义审计尚未完成。 |
| C5 | 支持的显式流与未追踪路径是否清晰？阻断能否归因到系统？ | 审包装丢失、任意 Python／第三方转换、模型改写与隐式流的边界；本机接收证据只能验证该受控路径。不可把网络／沙箱阻断归功于 AgentShield。 |

## D. 对照、公平性与复现

| ID | Reviewer 会追问什么？ | 回答所需证据／当前缺口 |
|---|---|---|
| D1 | 策略是否共享任务、腐化图、依赖契约和接收端？正常任务是否被全拒绝策略牺牲？ | 同源配对清单、逐样本轨迹、全分母 ASR/TCR/FPR；系统优越性不能只看安全率。静态／扫描／污点机制贡献与阈值策略变化须区分，不能修改输入偏袒一组。 |
| D2 | FIDES/APPA 是否是真实可比运行，而非原语或源码检查？ | [外部可行性记录](../EXTERNAL_FEASIBILITY.md)尚未给出完整配对运行；FIDES 的五个 lattice 断言不是系统对照。适配失败时明确收窄为内部测量研究，不能隐去差异。 |
| D3 | 作者构造、开发校准、独立保留与真实模型证据是否混用？ | 逐类披露来源与执行次数；36 项真实模型 UNRUN 不能推出模型效果。保留材料需在新协议冻结后一次性评估，不能反复调参仍称独立。 |
| D4 | 其他人能复核原始失败、实现版本和限制吗？ | Git 对象、原始 JSON/CSV、运行信息及失败记录；[历史验证](final-verification.json)可复核，但 CI／哈希不证明语义真值、统计有效性或第三方复现。 |
