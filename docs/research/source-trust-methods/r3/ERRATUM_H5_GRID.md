# R2 H5 命名勘误与 R3 修正

P1 成立。R2 统计生成代码/一致性门禁共享了错误网格 `[0,.01,.05,.10,.25,.50]`，
归一化宽度 `.50`；它不是 R1 H5 的 `[0,.05,.10,.25,.50,1.0]`、积分范围 `[0,1]`。
撤回历史定额场景的 `H5_safety_component_ONLY` 名称及其作为 H5 校准的引用。
历史 9,600 行、配置、图表、原代码 Git 对象和失败日志均原字节保留，不修改原始结果。
历史定额场景只能称“低错标率探索性 AUC 压力测试”；负面的共同故障覆盖结果不依赖该网格。

R3 将网格、积分范围与归一化宽度从冻结 R1 JSON 绑定读取，检查 H5 的六点 TCR 名称，
固定源协议 SHA256。新配置先提交，再生成新目录下的完整产物。
独立门禁单独读取 R1 协议，不导入生成器，也不再硬编码与实现同源的错误网格。
历史门禁仍可确认原数据内部一致，但明确返回 `R1_H5_grid_eligible=false` 和撤回名称。

已加入外部 R1 契约和解析积分的回归检查。正式网格下假想线性响应 `-.5p` 的 AUC 真值为
`-.25`；旧探索性范围为 `-.125`，因此不能混用 `-.05` 改善阈值的尺度。
R3 保留原随机流版本/种子；配对复跑的差异只来自定额场景的积分网格，
共同故障场景可逐记录比较。新定额结果仍只是安全组件 **toy 校准**，不是完整 H5 或防御实验。

完整联合功效、阈值价值授权、真实双人标注/审计与共同运行时外部适配仍是门禁。
